# Этап 7 — итог контролируемого сравнения RAG

Дата: 2026-09-23. Решение независимого ревью: **не включать по умолчанию query rewrite, BGE-M3 или Qwen3**. Код безопасной общей переформулировки оставлен выключенным (`RAG_QUERY_REWRITE_ENABLED=0`).

## Зафиксированные данные

До настройки retrieval снят манифест `.omx/snapshots/rag-stage7-2026-09-23/manifest.json` и сохранён `index.seed`. В корпусе 970 поддерживаемых файлов; SQLite FTS5 содержит **881 документ / 21 127 чанков**, Chroma — **21 127 embeddings**. SHA-256 корпуса: `e508f3f651b156da1ae47fee75187c48065b886e733d668a56b4e0abe7a1ecf0`; SHA-256 снимка индекса: `dd66c13982c4582eb640b3e25e8645cbebffe46b1cb1628fe7052cb7e7d8fd60`. Все 31 файла seed сверены с манифестом; обе SQLite-базы прошли `integrity_check`. Для измерений использовались отдельные рабочие копии seed, поскольку чтение Chroma может изменить его SQLite-файлы.

Прежний рост оценки **2/12 → 6/12 нельзя приписывать lexical-поиску**: одновременно увеличился корпус. Исторические `matrix.after2.json`/`matrix.after3.json` и результат 8/8 получены с правилами для формулировок контрольных вопросов. Эти правила удалены из production; артефакты сохранены как отвергнутая ветка эксперимента. Текущая таблица начинается с нового замера на фиксированном входе.

## Метод

Основной набор: `tests/fixtures/rag_eval/cases.v1.json` — восемь вопросов (5 чистая история, 3 загрязнённая). Независимый набор `holdout.v1.json` — восемь вопросов по общежитию, стипендиям, скидкам и мобильности (4+4). Все режимы одного модельного прогона используют одинаковые корпус, историю, `RAG_TOP_K=4`, пул кандидатов 16, лимиты контекста 4×1200/3600 символов. Сохранены raw dense и lexical top-5, объединённый candidate top-5, итоговый top-4, контекст модели, ответ, источники, policy diagnostics и результаты существующего evaluator по metadata. `policy-fallback` — **повторная policy/repair-проверка того же ответа hybrid** для изоляции стадии, а не отдельный production `AskService` вызов.

Tiny2 evaluator применяет CLS+L2 normalization, сверенные с production SentenceTransformer на четырёх русских запросах (максимальная координатная разница `9.69e-8`). BGE-M3 использует production `HuggingFaceEmbeddings.embed_query`; сверка модели при reembed дала максимальную разницу `3.84e-7`. Исходные id, текст, metadata всех **21 127** чанков BGE-индекса сверены с seed; lexical SQLite скопирован без изменений (совпадающий SHA-256). BGE manifest в `index.bge-m3/reembed_manifest.json` относится к оригинальному target; оценочные копии индекса создавались из него и затем удалены. Поиск без генерации и ответы сопоставляются раздельно: существующий evaluator оценивает соответствие источников, а не истинность вывода модели. Seed генерации не закреплён.

BGE primary на контрольных: **3/5 + 2/3**. Переформулировка Qwen3: **2/5 + 1/3** на контрольных. История не добавлялась к основному поисковому запросу.

Qwen2.5 переписывал запрос за 0,19–0,60 с на этих случаях и был принят в 3/8 основных и 5/8 независимых запросов. Qwen3 rewrite занимал в среднем 17,8 с (один таймаут 30 с), ухудшил контрольный top-5 с 4/8 до 3/8. Qwen3 как генератор при неизменном top-4 убрал наблюдавшиеся `unverified_filename` и ложную расшифровку «ВШЭ» в сравненных ответах, но среднее время генерации выросло с 1,66 до 15,1 с. `avg_total_time_ms` внутри матриц **не включает заранее выполненный rewrite/поиск**; эти времена нельзя читать как end-to-end latency.

Прерванный поздний повтор Qwen2.5 rewrite не создал матрицу: macOS завис на загрузке native dependencies при первом dense-поиске; для этого варианта используются завершённые файлы `matrix.query.*.rewrite2.json`, в которых backend уже нормирован и проверен на parity.

## Приёмка, безопасность и интерпретация

Критерий плана «ожидаемый документ в top-5 **каждого** контрольного вопроса» не выполнен ни одним вариантом. BGE-M3 в primary улучшил hit@5 до 5/8 на контрольных, но production hybrid с этим индексом снизил его до 3/8; на независимых темах BGE hybrid достиг 6/8, однако два raw ответа нарушили output policy и при ручном просмотре один ответ приписал документам неподтверждённые сроки. В текущем tiny2 hybrid один raw ответ содержал неподтверждённое имя файла; policy replay его устранил. Qwen3 лучше соблюдал оформление источников, но при отсутствии подходящего документа часто ответил «данных недостаточно» и не исправил retrieval. Автоматическая метрика по словам для смысла ответа груба; ручной разбор подтверждает, что вопросы о взысканиях иногда подменяются перечнем санкций, а ответы о пересдачах иногда опираются на рейтинги/отсрочки вместо правил пересдач. Следовательно, и критерий содержательного ответа не подтверждён.

Общая переформулировка реализована через отдельную локальную модель: сохраняется исходный запрос, дополнительный запрос проходит ограничение длины, проверку тематического сдвига/служебного текста и может только добавить кандидатов во второй dense+lexical проход. При ошибке остаются кандидаты исходного запроса; в diagnostics и обычные логи не пишутся текст вопроса, история, raw output или текст исключения. `RAG_QUERY_REWRITE_ENABLED=0` по умолчанию. Независимый ревьюер подтвердил отсутствие словарей по конкретным кейсам и одобрил исправление логов, но вынес **NO-GO** по качеству для default enable.

Тестировщик: полный `pytest` **271 passed**, `tests/test_rag.py` **51 passed**, `uv lock --check`, Ruff, isort и focused `ty` — PASS после последнего исправления. Тесты охватывают prompt injection/control marker, typed policy reasons, защиту логов, repair неподтверждённых ссылок, отсутствие записи fallback в память и ошибки второго retrieval. `black --check .` повторно завис на импорте `black` и был остановлен; предыдущий проход до последних точечных правок был зелёным (61 файл). Это ограничение среды, не заявленный успешный format gate. Детали: `.omx/reports/rag-stage7-2026-09-23/query-rewrite-tests.md`.

## Ручной smoke

В изолированном локальном web (`127.0.0.1:8768`, копия frozen index, отдельная тестовая БД) чистый вопрос о конкретных дисциплинарных действиях получил ответ за 10,3 с с четырьмя источниками. Ответ назвал использование ИИ при ВКР без указания, но также смешал последствия с действиями и процитировал регламент для работников. Следующий вопрос того же пользователя о сроках пересдач проверил загрязнённую историю: ответ не выдумал даты, однако его top-4 включил материалы об отсрочке и рейтинге вместо правил пересдач. В видимом ответе модель вывела внутреннее имя поля `untrusted_documents`. Это воспроизводимое нарушение найдено ручным прогоном, после чего выходная policy расширена на имена внутренних JSON-полей. Регрессионный тест проверяет typed `control_marker_leak` и замену такого ответа на `SAFE_POLICY_REFUSAL`; независимый ревьюер одобрил точечное исправление.

После перезапуска первый web-запрос попал в `rag_timeout_budget_exhausted` (190,8 с): macOS долго загружала native зависимости и модель embeddings; в найденных фрагментах при этом уже были правила и интервалы пересдач. Прогретый повтор того же вопроса в загрязнённой истории вернул за **3,1 с** интервалы «10 января — 15 февраля» и «1 сентября — 15 октября» из `studyspravka kontr`. В ответе не было утечки внутреннего поля. Это один ручной пример успешного поиска, а не основание включать rewrite по умолчанию: общие матрицы всё ещё не проходят критерий для каждого вопроса, а календарную актуальность дат отдельно не проверяли.

Реальный Telegram-бот `@ask_hse_docs_bot` на отдельной тестовой БД ответил на `/start`, показал меню, принял чистый контрольный вопрос через кнопку и выдал ответ с четырьмя источниками. Холодный первый запрос ушёл в `rag_timeout_budget_exhausted` за 20,3 с и показал фрагменты вместо ответа модели. Следовательно, ручной Telegram smoke подтвердил доставку и fallback, но **не подтвердил качество нормального ответа или загрязнённую историю Telegram**; это открытый пункт приёмки. Более ранний `manual-smoke.md` относится к исторической ветке с отклонёнными тематическими правилами и не доказывает качество текущего кода.

## Воспроизведение

Из корня репозитория, при установленном локальном Ollama с `qwen2.5:3b`/`qwen3:8b` и загруженной моделью embeddings. Копии `index.*` для отдельных прогонов создаются из seed заново; оригинальный seed не монтировать для записи.

```bash
uv sync --frozen --group dev
SNAP=.omx/snapshots/rag-stage7-2026-09-23
REPORT=.omx/reports/rag-stage7-2026-09-23
cp -cR "$SNAP/index.seed" "$SNAP/index.replay"
PYTHONPATH=. LLM_MODEL=qwen2.5:3b uv run python -m src.server.app.rag_stage7_evaluation \
  --snapshot-dir "$SNAP" --index-dir "$SNAP/index.replay" \
  --cases tests/fixtures/rag_eval/cases.v1.json \
  --output "$REPORT/matrix.replay.json"
cp -cR "$SNAP/index.seed" "$SNAP/index.rewrite.replay"
PYTHONPATH=. LLM_MODEL=qwen2.5:3b RAG_QUERY_REWRITE_MODEL=qwen2.5:3b \
  uv run python -m src.server.app.rag_stage7_evaluation \
  --snapshot-dir "$SNAP" --index-dir "$SNAP/index.rewrite.replay" \
  --cases tests/fixtures/rag_eval/holdout.v1.json \
  --modes hybrid --query-rewrite --output "$REPORT/matrix.rewrite.replay.json"
PYTHONPATH=. uv run pytest -q
uv lock --check
uv run ruff check .
uv run isort --check-only .
uv run ty check src/server/app/query_rewrite.py src/server/app/rag.py src/server/app/rag_stage7_evaluation.py
```

Для BGE-M3 создаётся отдельный индекс с теми же id/текстами/metadata, без повторного чтения и разбиения корпуса:

```bash
cp -cR "$SNAP/index.seed" "$SNAP/index.bge.source.replay"
PYTHONPATH=. uv run python -m src.server.app.reembed_frozen_index \
  --source "$SNAP/index.bge.source.replay" --target "$SNAP/index.bge-replay" \
  --model BAAI/bge-m3 --expected-count 21127
HF_EMBEDDING_MODEL=BAAI/bge-m3 HF_EMBEDDING_NORMALIZE=1 PYTHONPATH=. \
  LLM_MODEL=qwen2.5:3b uv run python -m src.server.app.rag_stage7_evaluation \
  --snapshot-dir "$SNAP" --index-dir "$SNAP/index.bge-replay" \
  --cases tests/fixtures/rag_eval/holdout.v1.json \
  --output "$REPORT/matrix.bge.replay.json"
```

Экспериментальные рабочие копии индекса после сохранения JSON удалены; `index.seed`, `index.bge.source`, `index.bge-m3` и все матрицы сохранены. Коммитов нет. Исходные изменения пользователя в документах, PDF, submodule и `graphify-out` не тронуты.

## Основание выбора моделей

Query rewrite — известный подход для RAG, но его эффект надо измерять на своём корпусе ([EMNLP 2023](https://aclanthology.org/2023.emnlp-main.322/)). [BGE-M3](https://huggingface.co/BAAI/bge-m3) поддерживает много языков и 1024-мерные dense-векторы; смена модели требует отдельного reembed индекса. [Qwen3 в Ollama](https://ollama.com/library/qwen3) поддерживает русский и локальный запуск; [API Ollama](https://ollama.com/blog/thinking) позволяет выключить thinking для ускорения, но конкретный выигрыш и качество в этом проекте ещё не измерялись.
