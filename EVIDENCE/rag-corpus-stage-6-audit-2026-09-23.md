# Аудит корпуса RAG перед этапом 7

Дата проверки: 2026-09-23. Аудит выполнен без переиндексации и без изменения
`data_and_documents` или рабочей Chroma/FTS-базы.

## Причины отказов

| Категория | Файлов |
| --- | ---: |
| Все файлы корпуса | 993 |
| PDF | 303 |
| DOCX | 674 |
| DOC, RTF, без расширения | 13, 1, 2 |
| Временные DOCX `~$`, исключаемые индексатором | 7 |
| Поддерживаемые файлы после исключения временных | 970 |
| Прочитанные DOCX / PDF | 578 / 224 |
| DOCX без извлекаемого текста | 89 |
| PDF без извлекаемого текста | 79 |

Итого 802 документа разобраны и 168 не разобраны. Доля файлов без извлекаемого
текста — 168/970 = **17,32%**; среди PDF — 79/303 = **26,07%**. Текущий
`src/server/chrome_langchain_db/lexical_index.sqlite3` содержит 802 документа и
20 353 чанка. Это совпадает с числом успешно разобранных файлов, но само по себе
не доказывает качество извлечённого текста.

Метод воспроизведения: обойти `data_and_documents`, оставить расширения
`.pdf/.html/.htm/.txt/.docx`, исключить DOCX с префиксом `~$`, вызвать
`load_document(path, root_dir=...)` и сгруппировать исключения `DOCX ... is
empty` и `PDF ... did not contain extractable text`. Итоговый отчёт
`.omx/reports/rag-corpus-stage-6-audit-2026-09-23.json` получен командой:

```bash
LOG_LEVEL=ERROR PYTHONPATH=. uv run --no-sync python -m src.server.app.index_documents \
  --input-dir data_and_documents \
  --persist-dir src/server/chrome_langchain_db \
  --audit-only \
  --report-json .omx/reports/rag-corpus-stage-6-audit-2026-09-23.json
```

Отчёт содержит результаты по каждому из 970 поддерживаемых файлов, счётчики
по расширению, статусу и причине, долю файлов без текста и показатели OCR.
Режим `--audit-only` не пишет в Chroma/FTS и не запускает embeddings.

Все 89 пустых DOCX содержат `word/media/` и имеют одноимённый PDF. Это не 89
независимых отсутствующих источников. Пример пары:
`data_and_documents/from_parsers/11.Выписка УС 29.11.23 № 14-О внес.изм.в Положение об акад.мобил.{docx,pdf}`.
По SHA256 найдено 30 групп точных дубликатов (38 дополнительных копий).
Дубликаты и пары следует учитывать при выборе OCR-приоритетов; исходные файлы
автоматически не удалялись.

Для следующего контролируемого сравнения зафиксирован digest поддерживаемого
корпуса (970 файлов):
`e508f3f651b156da1ae47fee75187c48065b886e733d668a56b4e0abe7a1ecf0`.
Алгоритм: отсортировать относительные POSIX-пути допустимых файлов без `~$`,
для каждого вычислить SHA256 содержимого, затем вычислить SHA256 конкатенации
`<relative-path>\0<file-sha256>\n` в этом порядке. Это отпечаток состава и байтов,
а не качества источников.

## Актуальность источников

`indexed_at` и время изменения файла фиксируют обработку/копирование, а не
действительность нормы. У 803 из 993 файлов год 2010–2026 отсутствует в имени;
год в имени также не доказывает устаревание. Ниже — выборочная сверка
приоритетных учебных источников с официальными страницами НИУ ВШЭ на
2026-09-23.

| Локальный источник | Официальный ориентир | Вывод для корпуса |
| --- | --- | --- |
| `Regulation.docx` | [ПОПАТКУС](https://www.hse.ru/docs/1026832917.html) | Реквизиты базовой редакции 2025 совпадают; карточка содержит изменения 31.03.2026 и 28.04.2026. Требуется сверка включения изменений. |
| `student_handbook/basic/Перенос второй пересдачи дисциплины и ее повторное изучение.docx` | [Текущая справка](https://www.hse.ru/studyspravka/repeated_courses) | Совпадение темы и названия; перед признанием актуальным требуется текстовое сравнение с текущей страницей и связанными памятками. |
| Документы о первой пересдаче в `student_handbook/basic` | [Текущая справка](https://www.hse.ru/studyspravka/repeated_courses) | Три документа о пересдачах уже есть в индексе; проверить связанные редакции и категории студентов. Проблема их отсутствия в top-5 относится к retrieval. |
| Старые положения о скидках 2018–2023 | [Перечень локальных актов](https://www.hse.ru/studyspravka/loc), [карточка прежнего положения](https://www.hse.ru/docs/807180592.html), [положение для набора 2026](https://www.hse.ru/docs/1193811775.html) | Разделять аудиторию до набора 2026 и с 2026/2027; документы 2023 года не считать общим текущим правилом без проверки применимости. |

Три локальные памятки о пересдачах не содержат дат `dd.mm.yyyy`. В корпусе
есть как консолидированные документы (например, три одинаковые копии ПВРО
2024), так и отдельные приказы об изменениях. Правильная метка для них —
`требует сверки редакции`, а не автоматическое `утратил силу`.

## Шум DOCX и приоритет очистки

Числовая плотность сама по себе даёт ложные срабатывания: шкалы оценок,
расписания и приказы закономерно содержат много цифр. Пример навигационного
шума — `data_and_documents/from_parsers/studyspravka_documents.docx`: в начале
есть «Высшая школа экономикиМеню», в конце — «карта сайта», между ними есть
полезное содержание. Метка качества должна быть объяснимой и сохранять
документ для последующей очистки.

В итоговом отчёте 176 из 578 разобранных DOCX получили метку `review`; ещё
89 пустых DOCX имеют диагностическую метку `media_heavy_short_text`, но не
попали в индекс. `studyspravka_documents.docx` отмечен `navigation_noise`,
а проверенные числовые шкалы оценок остались `clean`. В retrieval метка
`review` уменьшает итоговый RRF-балл до 75% и оставляет сильные совпадения
доступными. Эти метки применятся к рабочей выдаче после отдельной
переиндексации; текущий индекс в ходе аудита не менялся.

OCR для PDF без текста включается явно флагом `--enable-ocr` или настройкой
`DOCUMENT_OCR_ENABLED`; заданы пределы по страницам и времени, а в отчёте
разделены попытки, успешные документы, страницы и статусы ошибок. В этом
аудите OCR оставался выключен (`documents_attempted=0`), поскольку после
инвентаризации ещё нужно выбрать документы для обработки. Локальный
`tesseract` отсутствует; успешная ветка OCR проверена тестом с подменённым
движком. На приведённом выше реальном PDF явный OCR-прогон вернул
`ocr_attempted=true`, `ocr_status=unavailable` и
`reason=no_extractable_text`; реальное успешное распознавание здесь не
подтверждено.

Сначала целесообразно проверить 79 PDF без текста, в особенности пары с пустыми
DOCX, и документы, ожидаемые в провальных сценариях оценки. Полный OCR всех
PDF до ранжирования проблем по причинам не требуется. Для этапа 7 нужно
сохранить один и тот же корпус при сравнении стадий.

## Проверка реализации

- `PYTHONPATH=. uv run --no-sync pytest -q` с отдельными временными
  `LEXICAL_INDEX_PATH` и `WEB_AUTH_DATABASE_URL`: **227 passed**.
- `uv run --no-sync ruff check` и `black --check` для изменённых Python-файлов:
  без замечаний.
- `uv run --no-sync ty check` для четырёх изменённых модулей приложения:
  без диагностик.
- `git diff --check` для изменённых отслеживаемых файлов: без ошибок.

Без изоляции lexical-базы три старых теста `ask_question` получают реальные
документы из текущего индекса поверх подставленного dense-результата; при
изоляции все 227 тестов проходят. Это ограничение тестового окружения нужно
сохранить при повторном измерении, а не считать улучшением retrieval.
